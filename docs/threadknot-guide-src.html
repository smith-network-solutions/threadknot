Section 1

What is Threadknot?

Threadknot is an app for putting AI assistants to work on your projects — and keeping every one of those conversations organized in a single place.

Instead of typing commands into a black terminal window, you simply chat. You pick a project, type what you want done — "tidy up the homepage", "find out why the report is empty", "write a summary of these files" — and an AI agent gets to work. You watch it think, see every file it touches, and approve anything sensitive before it happens.

Three kinds of agents, one window

  • Claude Code — Anthropic's coding agent.
  • Codex — OpenAI's coding agent.
  • Hermes — remote helper agents running on other hardware you've connected.

You can switch agents mid-conversation — the new agent picks up right where the previous one left off.

Where does it run?

Entirely on your own computers. Threadknot is not a cloud service: there's no account to create and your projects never pass through anyone else's servers. Each machine runs its own copy of Threadknot, and — as you'll see in Section 4 — those copies can be joined into one fleet.

Section 2

A tour of the app

① The sidebar — your fleet at a glance

Every workspace (a named container for related work — more in Section 3) lists its conversations, newest first. Colored dots show what's busy, waiting for you, or idle. The search box finds any conversation by name.

② The chat — where the work happens

Type a message and press send. Above the message box you choose which agent and which model, how much freedom it has (read only / edits / full access), and whether it should plan first or build right away. When an agent wants to do something sensitive, a card appears asking you to allow or deny it.

③ The workspace panel — look around the project

  • Files — browse and preview everything in the project folder.
  • Git — see what changed, save (commit) and share (push) work.
  • Artifacts — documents the agents produced for you: PDFs, images, reports.
  • Terminal — a real command line, for when you want direct control.
Also worth knowing

Scheduled runs let an agent do a job on a timer (every morning, every hour…). Archive tucks finished conversations away — they can always be restored later from Settings.

Section 3

Workspaces — one project, many places

A workspace is a named home for one effort — a client, a product, a hobby — no matter where the actual folders live.

Say you run a project called Lighthouse. The website code lives on your desk machine, and the marketing material lives on your Mac. In Threadknot, that's one workspace with two folders — and every conversation about Lighthouse, on either machine, appears in the same list in your sidebar.

The three simple rules

  • A workspace holds folders and conversations. Rename it any time (right-click → Rename workspace) — the new name appears on every connected machine.
  • A folder always lives on exactly one machine. Threadknot never copies or moves your files between machines.
  • A conversation (thread) starts in one folder on one machine and stays there for good — so its history, files and results are always exactly where the work happened.
Where did “projects” go?

If you used Threadknot before workspaces existed: nothing was lost. Each of your projects simply became a workspace of the same name, with its folder and all its conversations intact.

Section 4

Connecting your machines together

Pairing two machines takes one copy-paste. After that, they trust each other completely and find each other automatically.

On the other machine, open Threadknot → Settings and copy its LAN URL (a web address that includes its secret key).
On this machine, open Settings → machines → pair, paste the address, and click pair machines.
Done. Both machines now show each other with a green “online” dot. You never have to do this again for that pair.

They find each other on their own

Home routers reshuffle network addresses from time to time. Threadknot doesn't care: each machine has a permanent identity (like a fingerprint), and machines announce themselves on your network and recognize each other by identity, never by address. If a machine comes back at a new address — or even a new port — its partners re-find it in seconds, automatically. Unpaired Threadknots on your network politely show up as “found on LAN”, one click from pairing.

What pairing does not do

  • It does not copy files between machines.
  • It does not send anything over the internet — traffic stays on your network.
  • It does not let anyone without a key in. Keys are stored privately on each machine and are never shown to browsers or phones.
Good to know

Paired machines trust each other fully — pairing is for computers that are all yours. To end the relationship, click remove next to the machine in Settings.

Section 5

Working across machines, day to day

Once machines are paired, “where the work runs” becomes a simple question Threadknot asks you at the right moment.

Starting a conversation somewhere else

Click + on a workspace. If there's a real choice to make, a little menu appears:

  • Pick an existing folder and the conversation starts there instantly.
  • Pick “Set up on …” and Threadknot shows you that machine's folders — choose one, and it joins the workspace with your new conversation ready to go.

Everything streams live

A conversation running on another machine looks and feels local. The agent's progress streams to your screen as it happens; you can approve requests, interrupt, rename — all from where you're sitting. A small machine tag on each conversation shows where it lives.

  • Files tab → browse the remote folder, preview images and PDFs.
  • Git tab → see changes and commit on the remote machine.
  • Terminal tab → a live command line on that machine. What you type here runs there.
  • Artifacts tab → open and download documents the remote agent produced.
If a machine is asleep or unplugged

Its tag goes grey and its options are disabled — nothing breaks. The moment it's back on the network, the dot turns green and everything resumes.

THREADKNOT7
Section 6

How your request travels (and why it's safe)

One rule explains everything: the machine that owns the folder does the work and keeps the records. Every other machine is just a window onto it.

Why this design is nice

  • Nothing is duplicated. A conversation's history lives in exactly one place — with the files it worked on.
  • Any machine can be the window. Sit at any computer (or use your phone) and drive the whole fleet.
  • Impersonation doesn't work. Before trusting a connection, Threadknot always checks the other side's permanent identity — an address alone is never enough.
  • A machine going offline is boring. The rest of the fleet carries on; that machine's work waits safely for its return.

Section 7

Threadknot on your phone

Kick off a job at your desk, approve its questions from the sofa, and get a buzz when it's done.

Two ways to connect

Any browser: open the LAN URL from Settings on your phone's browser. That's it — the full app, sized for a phone.

The Threadknot mobile app: the nicer everyday option. It adds:

  • Face/fingerprint lock — the app locks itself and opens with a glance.
  • Push notifications — “finished”, “needs your approval”, “hit an error” arrive as normal phone notifications, even with the app closed.
  • Multiple servers — keep every Threadknot machine in one list and switch with a tap.
  • Its own key — the phone gets a private, revocable pass. Lost the phone? Revoke it from the desktop in one click; nothing else changes.

And because of Section 5…

Your phone connects to one machine, but that machine can reach the whole fleet. Phone → desk machine → Mac works exactly like sitting at the desk.

Pairing your phone

In the mobile app, tap Add server and paste the same LAN URL from desktop Settings. The app trades that for its own private pass and forgets the master key immediately.

Section 8

Everyday recipes

Pair a new machine

Install and open Threadknot on the new machine.
Copy its LAN URL from Settings there.
On your main machine: Settings → machines → pair → paste → pair machines.

Start a conversation on another machine

Click + on the workspace.
Pick one of its folders — or “Set up on <machine>…” and choose a folder there.
Chat normally. The machine tag reminds you where it's running.

Bring another machine's folder into a workspace

Right-click the workspace → Machines & folders…
Under add a folder, pick the machine, then browse to the folder.
It appears as part of the workspace on every connected machine.

Rename a workspace

Right-click it → Rename workspace. The name updates on every machine in the workspace.

Remove a folder from a workspace

Right-click → Machines & folders… → remove. Nothing is deleted — the folder simply becomes its own workspace on its machine.

Finish a conversation

Hover it → ⋯ → Archive to file it away (restorable from Settings → archives), or Delete to remove it for good.

Rename this machine

Settings → machines → rename next to “this machine”. That's the name other machines (and machine tags) show.

If something looks stuck

Check Settings → machines first: a grey dot means that machine is off or unreachable. Wake it and everything resumes by itself — reconnection is automatic, always.

Section 9

Words Threadknot uses

AgentAn AI assistant that can actually do things — read and edit files, run commands, produce documents. Threadknot drives Claude Code, Codex and Hermes agents.
WorkspaceA named container in the sidebar for one effort. Holds folders (possibly on several machines) and all their conversations.
ThreadOne conversation with an agent, in one folder, on one machine. Stays on that machine forever.
FolderA real directory on one of your machines where an agent works. Threadknot never moves it or copies it elsewhere.
MachineAny computer running Threadknot. Paired machines form your fleet.
PairingThe one-time paste that makes two machines trust each other, both ways.
LAN URLThe private web address (with built-in key) a Threadknot machine shows in Settings. Used to connect phones and to pair machines.
Machine tagThe small label on a conversation showing which machine it lives on. Grey means that machine is currently offline.
ArtifactA document an agent produced for you — a PDF, image, spreadsheet, report. Kept safe even if the original file later changes.
ArchiveWhere finished conversations rest. They're out of the sidebar but fully restorable, including their history.
Plan / BuildTwo ways to start: Plan makes the agent propose an approach for your approval first; Build lets it get straight to work.
Access levelHow much freedom the agent has: read only, allowed to edit, or full access. You choose per conversation.
